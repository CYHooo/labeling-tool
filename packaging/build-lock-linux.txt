# Exact versions of EVERY package in the Linux build environment, direct
# and transitive. Used as a pip constraint (-c) together with
# build-constraints.txt, locally and in CI.
#
# Why: the runtime id measures the runtime layer's files, so any drift in a
# transitive dependency (a new filelock, jinja2, sympy ...) would move it and
# push a 1.5 GB full reinstall onto every user, for nothing. With everything
# pinned, two builds of the same lock produce the same runtime layer -- on
# CI or on a local machine -- and a runtime change happens only when this
# file changes.
#
# Upgrading anything here IS a runtime change: expect the next release to be
# a full install. Regenerate from a FRESH venv (never the runner's system
# Python, whose preinstalled packages vary by image), then `pip freeze`.
# sam2 is installed from git by its own pinned commit, so it is not listed.
#
# This lock is kept in parity with build-lock.txt (the Windows lock) by
# packaging/lock_parity.py / labeling_tool/tests/test_lock_parity.py: every
# package present in both locks must pin the same version, and every
# package present in only one must be declared in lock_parity.PLATFORM_ONLY
# (or lock_parity.VERSION_MAY_DIFFER for an unavoidable version split) with
# a reason.
