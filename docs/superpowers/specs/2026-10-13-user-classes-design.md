# 用户追加类别（SAM · 画笔）— 设计

日期：2026-10-13
状态：设计已逐段确认，待审阅
服务器接口提案：`2026-10-13-api-v1.0.16-classes-proposal.ko.md`（韩语，交给后端，基于 api-reference v1.0.15）

## 1. 背景与目标

标注窗口现在只有两个类别：균열（线状）和 박리（面状）。SAM 确认固定写入 박리，画笔只能在这两个
类别之间切换。以后会出现事先不知道的新损伤类别（例如 백태、누수、철근 노출），需要用户在工具里
**手动追加**，并且 SAM 和画笔都能用新类别标注、上传到服务器。

同一批改动还包括一项小改动：按 S / Ctrl+S 保存时，先自动确认未确认的 SAM 选区和 보수 구역 点，
SAM 点完不必再按 Enter（与 0.2.17「换照片时自动确认」的规则一致）。两者一起发布。

**目标**

1. 用户可以追加类别（名称 + 颜色）；所有用户、所有作业共用同一张类别表，同一个像素值处处含义相同。
2. SAM 和画笔都写入「当前类别」；类别选择器在 브러시 和 SAM 页面共用。
3. 新类别随掩码上传，服务器能拿到每个新类别的面积。
4. 服务器尚未升级时，新客户端照常工作（只有 균열 / 박리）。
5. 按 S 保存时自动确认未确认的编辑。

**成功标准**

- 在 A 电脑追加「백태」，B 电脑同步后看到同一个编号；B 上传的掩码里该编号就是 백태。
- 选中 백태 后用 SAM 点一下、按 S，掩码文件里出现该编号的像素，上传的 V4 里带 `classAreas`。
- 只用 균열 / 박리 时，上传请求与现在逐字节相同（除 `editBatchId` 等本来就变的值）。
- 服务器没有 V5 时，界面只显示 균열 / 박리，「+」不可用并说明原因，其余功能不受影响。

**不做**

- 删除、改名、改色（类别一旦用过，掩码里就有它的像素；改动交给服务器管理员）。
- 线状的新类别（新类别一律面状：只统计面积，画笔不细化）。
- AI 自动检测新类别（Detected 掩码仍只有 0/1/2）。
- 标注工具的账号登录（v1.0.15 的앱账号体系另议）。

## 2. 关键决定（已与用户确认）

| 问题 | 决定 |
|---|---|
| 类别编号由谁分配 | **服务器统一管理**（方案一）。新接口 V5 查询、V6 追加；客户端缓存 |
| 上传策略 | 服务器一起扩展：mask PNG 原样带新编号，V4 增加 `classAreas` |
| 适用范围 | SAM 和画笔都能用新类别 |
| 类别表范围 | 全局共用（按服务器区分缓存） |
| 新类别统计 | 一律面状：面积 mm² + 像素数 |
| 重叠 | 一个像素一个类别；균열 最优先；面状类别之间后画的优先 |
| 15cm 경계 | 新类别也算进보수 범위（所有类别的并集） |
| 选择器 | 下拉框 + 「+」按钮，数字键 1～9 |
| 发布 | 「按 S 自动确认」与类别功能一起发布 |

## 3. 服务器接口（摘要）

详见韩语提案。基于 v1.0.15，本地 포토뷰어 部分（V0～V4）与 v1.0.12 相同。

- **V5** `GET /api/viewer/classes/`（`X-Viewer-Api-Key`）→ `classes[]`：`classId`、`name`、`kind`
  （`line` / `area`）、`color`（`#RRGGBB`）、`builtin`。1 = 균열（line）、2 = 박리（area）固定存在。
- **V6** `POST /api/viewer/classes/`，body `{name, color}` → `201` 新类别；同名（去首尾空格、不区分大小写）
  → `200` 返回已有类别。编号 3～254 由服务器分配，用完返回 `409 CLASS_LIMIT_EXCEEDED`。
- **V4** `items[].classAreas`（可选）：`[{classId, areaMm2, pixelCount}]`，只列 3 号及以上。
  `crackMetrics`、`defectType`（0/1/2）不变。
- **像素值定义**（补进「파일명 규칙」）：`mask_*`、`high_*`：0 = 배경、1 = 균열、2 = 박리、3～254 = V5 类别；
  255 保留（旧二值掩码识别）。`15_*` 不变。
- **网页影响**：`high_*` 由网页直接显示，需要按 V5 的颜色画 3 以上的值。

## 4. 客户端设计

### 4.1 类别表 `labeling_tool/core/classes.py`（新）

- `LabelClass(id, name, kind, color, builtin)`，`ClassRegistry`：按 id 排序的有序表；
  内置 1 균열、2 박리 永远存在（服务器不可达时也有）。内置类别的显示名走 i18n（`cat_crack` /
  `cat_spalling`），新类别显示用户输入的名称，不翻译。
- 缓存：`user_data_home()/label-classes/<host>.json`（host 取自 BASE URL，不同服务器分开）；原子写入；
  文件损坏时忽略缓存、只用内置类别，不覆盖原文件以外的数据。
- 同步时机：标注窗口打开时（后台线程，先用缓存）、上传前（upload worker 内再同步一次）；连不上或出错时用缓存（404 除外，见下一行）。
  V5 返回 404 视为「服务器不支持」：只用内置类别，「+」禁用。
- `ViewerApiClient` 增加 `list_classes()`、`add_class(name, color)`。
- 颜色自动挑选：预置一组与红、绿、灰明显不同的调色板，挑第一个未被使用的；都用过时按色相均分生成。

### 4.2 掩码编解码 `mask_codec.py`

- `encode_label_mask(layers: dict[int, ndarray], order) -> ndarray`：按优先级从低到高写入，
  균열（1）最后写，确保最优先。
- `decode_mask(raw, path) -> dict[int, ndarray]`：
  单通道且 `max <= 254` → 按像素值拆层（包括未知编号）；3 通道旧 RGB、0/255 旧二值的判断规则不变
  （只产生 1、2 层）。
- 调用方（`mask_io`、`upload_worker`、`main_window`、`exporter`、`derived_masks`、
  `overlay_painter`）从 `(crack, spalling)` 元组改为字典。

### 4.3 画布 `image_canvas.py`

- `layers: dict[int, ndarray]` 取代两个固定属性；`brush_mask_crack` / `brush_mask_spalling`
  保留为 `layers[1]` / `layers[2]` 的只读属性，减少改动面。
- `current_class_id` 取代 `current_category`。画笔、SAM 确认都写入当前类别。
- **面状互斥**：在面状类别上画或 SAM 确认时，同一像素里其他面状类别的层清零（后画优先）；
  균열 层不受影响（균열 本来就覆盖其他类别）。
- 균열（line）在 SAM 下不可选：SAM 页面里 균열 项禁用；进入 SAM 时若当前是 균열，切到 박리。
- 撤销历史：已经按层名字典存储，改成按 id 字典即可；新层第一次被画时加入。
- 未知编号的层：灰色显示，名称显示为 `#7`；保存、上传原样保留，不能被选为当前类别。
- 叠加颜色、画笔光标颜色从类别表取。

### 4.4 派生掩码 `derived_masks.py`

- 하이라이트：所有类别都膨胀显示，按同一优先级编码，像素值与 mask 一致。
- 15cm 경계：所有类别的并集（新类别也算보수 범위）。

### 4.5 上传与统计

- `crackMetrics` 不变：균열 长度宽度、`spallingMm2`、`defectType` 只看 1、2。
- `classAreas`：每个出现的 3 号以上类别，`areaMm2 = pixelCount / pxPerMm²`（复用
  `compute_spalling_area_mm2` 的算法）。没有新类别时不发送该字段。
- 上传前先同步一次 V5。同步后仍不认识的编号（服务器上不存在）不写进 `classAreas`
  （否则 V4 返回 400），但像素留在 mask 里，并在状态栏 / 日志提示。
- 本地 `Result/`：结果图按类别颜色画；结果文本每个新类别追加一行面积。

### 4.6 界面

- **类别选择器**（新组件）：`카테고리 [■ 2  박리 ▾] [+]`，下拉项带色块和数字；
  브러시 和 SAM 两个页面各放一个实例（不做控件搬家），都绑定同一个类别表和「当前类别」，
  一处改变另一处同步。보기 / 보수 구역 页面没有选择器。
- 数字键 1～9 选第 N 个类别（替代现在的 1 / 2）。
- 「+」→ 追加对话框：名称（必填，去首尾空格，最长 50 字）+ 颜色（自动挑选，可点开 QColorDialog）。
  调用 V6；离线、404 或失败时显示原因，类别表不变。
- 现有「균열 / 박리」两个大按钮移除；`#catCrack` / `#catSpalling` 样式随之删除。
- 文案：SAM 说明里的「박리로 기록」改为「선택한 카테고리로 기록」；帮助对话框、术语表同步。
- 约束：侧边栏最小宽度 340 px，900 px 高度下任何工具不出现滚动条（韩 / 中 / 英）。

### 4.7 按 S 保存时自动确认

`_on_brush_save`（S、Ctrl+S、保存按钮）先调用 `_confirm_pending_edits()`，再保存；
状态栏显示自动确认的提示（与换照片相同）。

## 5. 兼容性与上线顺序

- 旧掩码（0/1/2、旧 RGB、旧 0/255 二值）读取结果不变。
- 服务器未升级：V5 404 → 只有内置类别；V4 不带 `classAreas` → 请求与现在相同。新客户端可以先发布。
- 服务器升级后、客户端未升级：旧客户端从不调用 V5 / V6，也不发送 `classAreas`，不受影响；
  但旧客户端读到含新编号的掩码时会解错：旧规则只认 `max <= 2` 的标签图，否则当作 0/255 二值掩码，
  整张掩码会被读成一个类别。因此新类别投入使用前，所有标注电脑应先升级到新版。
- 顺序：提案交后端 → 后端实现 V5 / V6 / `classAreas` 的同时客户端开发（本地模拟服务器测试）→
  后端上线后联调 → 发布客户端。
