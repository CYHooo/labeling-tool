# GS-xi API 명세서 - v.1.0.16 변경 제안 (손상 카테고리 추가)

기준 문서: **api-reference v1.0.15** — 아래 항목만 추가·변경하고 나머지는 v1.0.15 그대로입니다.
작성: 로컬 포토뷰어(LM Labeling Tool) 측 · 2026-10-13 · 상태: **제안 (서버 검토 필요)**

> **v1.0.16 변경 이력 (제안)**
> - **손상 카테고리 추가**: 지금까지 마스크 픽셀값은 0(배경)·1(균열)·2(박리) 세 가지뿐이었습니다.
>   현장에서 미리 알 수 없는 손상(예: 백태, 누수, 철근 노출)을 로컬 포토뷰어에서 **직접 추가**해
>   SAM·브러시로 라벨링하고 업로드할 수 있도록, 카테고리 목록을 **서버가 관리**합니다.
>   - 여러 PC가 각자 번호를 붙이면 같은 픽셀값이 PC마다 다른 손상을 뜻하게 되므로, 번호는 서버가 매깁니다.
>   - [V5](#v5-카테고리-목록-조회) `GET /api/viewer/classes/` · [V6](#v6-카테고리-추가) `POST /api/viewer/classes/` 추가
>   - [V4](#v4-주석-배치-등록) `items[].classAreas` (array, 선택) 추가 — 추가 카테고리별 면적
>   - [파일명 규칙](#로컬-포토뷰어-결과-3단계-v2v4)에 **마스크 픽셀값 정의** 추가 (`mask_*` · `high_*`: 3~254 = 추가 카테고리)
>   - 오류 코드 `CLASS_LIMIT_EXCEEDED` 추가
> - **하위 호환**: `crackMetrics`·`defectType`(0 균열 · 1 박리 · 2 혼합)은 그대로입니다. 추가 카테고리를 쓰지 않는
>   요청은 v1.0.15와 완전히 같습니다. 구버전 포토뷰어는 V5·V6을 호출하지 않고 `classAreas`도 보내지 않습니다.

## 파일명 규칙 — 로컬 포토뷰어 결과 (추가 내용)

**마스크 픽셀값** (단일 채널 PNG, 정수 라벨):

| 값 | 의미 | 적용 파일 |
|----|------|-----------|
| `0` | 배경 | `mask_*`, `high_*` |
| `1` | 균열 | `mask_*`, `high_*` |
| `2` | 박리 | `mask_*`, `high_*` |
| `3` ~ `254` | [V5](#v5-카테고리-목록-조회)의 추가 카테고리 (`classId`) | `mask_*`, `high_*` |
| `255` | **사용 안 함** (구형 0/255 이진 마스크 판별용으로 남겨 둠) | — |

- 한 픽셀은 한 카테고리만 가집니다. 겹치면 **균열이 우선**합니다.
- `15_*`는 종전대로 **0=배경, 255=15cm 경계**이며, 추가 카테고리 영역도 경계 계산에 포함됩니다.
- AI 서버 결과(`mask_*`, I4·I6)는 종전대로 0·1·2만 사용합니다.
- **웹 photo_viewer 영향**: `high_*`를 직접 표시하므로 3 이상의 값은 [V5](#v5-카테고리-목록-조회)의 `color`로
  칠해야 합니다. 색을 모르는 값은 회색 등으로 표시하는 것을 권장합니다.

## V5. 카테고리 목록 조회

로컬 포토뷰어가 작업 목록·라벨링 화면을 열 때 호출해 카테고리 목록을 맞춥니다. 내장 카테고리(1 균열 · 2 박리)를 포함한
**전체 목록**을 `classId` 오름차순으로 반환합니다.

| 항목 | 값 |
|------|-----|
| Method | `GET` |
| URL | `/api/viewer/classes/` |
| 인증 | `X-Viewer-Api-Key` |

### Response
>
> | Status | 설명 |
> |--------|------|
> | `200` | 성공 |
>
> #### Body (JSON)
>
> | 필드 | 타입 | 설명 |
> |------|------|------|
> | `classes` | array | 카테고리 목록 (`classId` 오름차순) |
> | &nbsp;&nbsp;&nbsp;&nbsp;└ `classId` | int | 마스크 픽셀값 (1~254). 1 = 균열, 2 = 박리 (고정) |
> | &nbsp;&nbsp;&nbsp;&nbsp;└ `name` | string | 표시 이름. 내장 카테고리는 `crack` · `spalling` (클라이언트가 언어별로 번역) |
> | &nbsp;&nbsp;&nbsp;&nbsp;└ `kind` | string | `line` (선형, 균열만) · `area` (면형) |
> | &nbsp;&nbsp;&nbsp;&nbsp;└ `color` | string | 표시 색 `#RRGGBB` |
> | &nbsp;&nbsp;&nbsp;&nbsp;└ `builtin` | bool | 내장 여부 (1·2만 `true`) |
> | &nbsp;&nbsp;&nbsp;&nbsp;└ `createdAt` | string | ISO 8601 (내장은 `null`) |

### curl

```bash
curl -s "$BASE/api/viewer/classes/" \
  -H "X-Viewer-Api-Key: $VIEWER_KEY" | python3 -m json.tool
```

**응답 예시**

```json
{
  "classes": [
    {"classId": 1, "name": "crack",    "kind": "line", "color": "#FF3C3C", "builtin": true,  "createdAt": null},
    {"classId": 2, "name": "spalling", "kind": "area", "color": "#3CE63C", "builtin": true,  "createdAt": null},
    {"classId": 3, "name": "백태",     "kind": "area", "color": "#3C8CFF", "builtin": false, "createdAt": "2026-10-20T09:12:03+09:00"}
  ]
}
```

## V6. 카테고리 추가

로컬 포토뷰어에서 사용자가 새 손상 카테고리를 추가할 때 호출합니다. 서버가 **3부터 비어 있는 가장 작은 번호**를
배정합니다. 추가된 카테고리는 모든 PC·모든 세션에서 같은 번호로 쓰입니다.

| 항목 | 값 |
|------|-----|
| Method | `POST` |
| URL | `/api/viewer/classes/` |
| 인증 | `X-Viewer-Api-Key` |

**같은 이름 처리:** 앞뒤 공백을 제거하고 **대소문자를 구분하지 않고** 비교해, 이미 있는 이름이면 새로 만들지 않고
그 카테고리를 `200`으로 반환합니다(내장 `crack`·`spalling` 포함). 두 사람이 동시에 같은 이름을 추가해도 하나만 생깁니다.

**삭제·이름 변경 API는 두지 않습니다.** 한 번 쓰인 카테고리는 마스크 픽셀값으로 남아 있으므로, 변경은 서버 관리자가
관리 화면에서 처리합니다(번호 재사용 금지 권장).

### Request
>
> #### Body (JSON)
>
> | 필드 | 타입 | 필수 | 설명 |
> |------|------|:----:|------|
> | `name` | string | O | 표시 이름. 앞뒤 공백 제거 후 1~50자 |
> | `color` | string | | `#RRGGBB`. 생략 시 서버가 지정 |

### Response
>
> | Status | 설명 |
> |--------|------|
> | `201` | 새로 추가됨 |
> | `200` | 같은 이름이 이미 있음 (기존 카테고리 반환) |
>
> #### Body (JSON)
>
> V5 `classes[]`의 항목 1개와 같은 구조.

### curl

```bash
curl -s -X POST "$BASE/api/viewer/classes/" \
  -H "Content-Type: application/json" \
  -H "X-Viewer-Api-Key: $VIEWER_KEY" \
  -d '{"name": "누수", "color": "#FFAA00"}' | python3 -m json.tool
```

**응답 예시 (`201`)**

```json
{"classId": 4, "name": "누수", "kind": "area", "color": "#FFAA00", "builtin": false, "createdAt": "2026-10-20T10:03:41+09:00"}
```

## V4. 주석 배치 등록 (변경)

`items[]`에 아래 필드를 **선택**으로 추가합니다. 나머지 필드·`crackMetrics`·멱등성 규칙은 v1.0.15와 같습니다.

> | 필드 | 타입 | 필수 | 설명 |
> |------|------|:----:|------|
> | &nbsp;&nbsp;&nbsp;&nbsp;└ `classAreas` | array | | 이 사진 마스크에 있는 **추가 카테고리(3 이상)** 별 면적. 없으면 생략 |
> | &nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;└ `classId` | int | O | V5의 `classId` (3~254) |
> | &nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;└ `areaMm2` | float | O | 면적 mm² (`pixelCount / pxPerMm²`) |
> | &nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;└ `pixelCount` | int | O | 마스크에서 해당 값의 픽셀 수 |
>
> - 박리 면적은 종전대로 `crackMetrics.spallingMm2`에 넣고 `classAreas`에는 넣지 않습니다.
> - `defectType`은 종전대로 균열·박리만 보고 정합니다 (0 균열 · 1 박리 · 2 혼합). 추가 카테고리만 있는 사진의
>   `defectType` 처리는 **서버 측 결정 필요** — 제안: 필드 생략 허용.
> - 서버는 `crackMetrics`와 마찬가지로 값을 **재계산하지 않고** 저장합니다.
> - V5에 없는 `classId`가 오면 `400 MISSING_FIELDS` (`details.classId`).

**요청 예시 (item 일부)**

```json
{
  "timestamp": 1717572612000,
  "maskS3Key": "results/43/masks/mask_1717572612000.png",
  "crackMetrics": {"lengthMm": 1234.5, "avgWidthMm": 0.8, "maxWidthMm": 1.2,
                   "spallingMm2": 5300.0, "defectType": 2, "pxPerMm": 4.52},
  "classAreas": [
    {"classId": 3, "areaMm2": 1520.4, "pixelCount": 31060},
    {"classId": 4, "areaMm2": 212.0,  "pixelCount": 4331}
  ]
}
```

## 공통 오류 응답 — 코드 추가

| code | HTTP | 의미 | 주로 발생 API |
|------|------|------|---------------|
| `CLASS_LIMIT_EXCEEDED` | 409 | 카테고리 번호(3~254)를 모두 사용함 | V6 |

`UNAUTHORIZED`·`MISSING_FIELDS`의 적용 API에 V5·V6을 추가합니다.

## 서버 측 확인 요청

1. V1 응답에 사진별 `classAreas`를 함께 돌려줄지 (로컬 포토뷰어는 마스크에서 다시 계산하므로 필수 아님).
2. 추가 카테고리만 있는 사진의 `defectType` 값 (위 제안: 생략 허용).
3. 웹 대시보드에서 추가 카테고리 목록·면적을 어떻게 보여줄지 (`high_*` 색칠 포함).
4. 카테고리 관리(이름 수정·숨김)를 관리 화면에서 할지.
